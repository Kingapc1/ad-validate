เรื่องต้องตัดสินใจก่อนล็อก Sprint

Tech Lead และ PO ต้องยืนยัน backend stack/service boundary, Google Ads credentials และ API permission, tag-health contract, rule inventory, source of truth ของ job/account, scan expiry, ผู้อนุมัติ Warning/Manual และวิธีรันงานเบื้องหลัง (queue worker, scheduler หรือ cron)

PRD ระบุ scan orchestration, retry และ expiry แต่ยังไม่ได้กำหนด cron job หรือการสแกนแคมเปญอัตโนมัติตามเวลา

ขอบเขตโครงการ

ภายในตุลาคม

  • Google Ads vertical slice และ precondition gate
  • versioned rules, findings, Critical gate, remediation, audit
  • outcome callback แบบ idempotent พร้อม retry
  • UAT กับทีม DMS และคู่มือใช้งาน

หลังตุลาคม / รอยืนยัน

  • Meta/TikTok production connectors และ rules
  • การสแกนแคมเปญอัตโนมัติตามเวลา
  • admin UI สำหรับจัดการ rule หาก Tech Lead เลือก code configuration
  • การ deploy production ขึ้นกับ release decision

กรอบติดตามผล

ใช้กรอบ Define → Measure → Analyze → Improve → Control เพื่อเชื่อมงานส่งมอบกับผลลัพธ์หลังใช้งาน

D · Defineนิยามปัญหาการปล่อยแคมเปญที่ยังมี Critical finding
M · Measureเก็บ baseline เวลาตรวจและ incident ก่อน pilot
A · Analyzeจัดกลุ่ม finding ตาม Setup, Configuration และ Customization
I · Improveใช้ Google runner, fix/re-scan และ gate ลดความผิดพลาด
C · Controlใช้ audit, rule version และ UAT/release checklist ตรวจย้อนหลัง

ผู้ใช้ที่เกี่ยวข้อง

DMS Operator / MCC

  • รัน validation, ดู finding, แก้และตรวจซ้ำ
  • ต้องเห็นเหตุผลที่กด proceed ไม่ได้

DMS Lead / Reviewer

  • ยืนยัน Warning/Manual exception ตามสิทธิ์
  • ตรวจ audit และผล UAT

Web / Tracking Team

  • แก้ tag, script, GTM และ conversion นอกระบบ
  • ต้องมี evidence และวิธี re-scan

New Job / upstream system

  • ส่ง job/account context
  • รับ outcome เพื่อเปิดขั้น Send Mail
